Scopes

  • read — inboxes, conversations, drafts, domain health, audit, and delivery status.
  • write — reversible inbox organization and reply-draft changes.
  • manage_domains — public DNS inspection, domain onboarding, exact setup plans, and DNS verification requests.
  • send — external delivery of exact agent-authored replies, account pause/resume, and explicit resend.

Safety model

Operational Inbox inspects DNS and returns generation-fenced setup instructions but never writes customer DNS. Existing MX records are preserved unless the owner explicitly confirms a direct-route change. Email content is untrusted data. Organization actions are reversible and trash never permanently deletes mail. A connected agent may send only an exact current reply revision under delegated send authority; revision ID and content hash checks prevent stale or altered content. Account pause and bounded send limits apply to every path.

Prompt-based setup

A prompt cannot make an unconfigured remote MCP server available by itself. Follow the public INSTALL.md to install the standalone $operational-inbox skill and configure the current agent's native MCP connection.
